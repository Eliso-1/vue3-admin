## 排查并修复「ElMessage 全局不生效」

**现象**：`ElMessage` / `ElMessageBox` 在项目里弹不出来（用户前期曾看到过弹窗，后变为完全不显示）。

**根因**：项目使用 Element Plus 按需自动引入（`unplugin-vue-components` + `unplugin-auto-import` + `ElementPlusResolver`）。
- 模板里的组件（`<el-button>`、`<el-menu>` 等）→ 插件会自动注入组件本身及其 CSS，所以正常。
- `ElMessage`、`ElMessageBox` 这类**函数式 API** 通过 `import { ElMessage } from 'element-plus'` 显式引入 → **绕过自动注入样式的插件**，而项目从未引入过 Element Plus 的任何全局 CSS。
- 结果：弹窗 DOM 被创建，但没有任何 CSS（无定位/背景/层级）→ 页面上看不见，表现为"不生效"。

**修复（用户选方案 B：按需精确引入）**：在 3 处显式 import 的地方补上对应 CSS：
- `src/utils/request.js` → `import 'element-plus/es/components/message/style/css'`
- `src/views/login/index.vue` → 同上
- `src/layout/components/Header.vue` → message + `element-plus/es/components/message-box/style/css`

**验证**：
- `message/style/css.mjs` 内部自带 `theme-chalk/el-message.css` + base + badge。
- `message-box/style/css.mjs` 内部自带 `overlay/style/css.mjs`（遮罩）+ base + input + button + `el-message-box.css`，故无需再单独引入 overlay。
- `npm run build` 通过；产物 `dist/assets/index-*.css` 中确认含 `.el-message`、`.el-message-box`、`.el-overlay`。

## 修复构建报错：路由导入路径写错（view 少了 s）

**报错**：`[plugin:vite:import-analysis] Failed to resolve import "@/view/login/index.vue" from "src/router/index.js"`

**原因**：`src/router/index.js` 第 34 行把 `@/views/` 写成了 `@/view/`（漏了 s）。
项目实际目录是 **`src/views/`（复数）**，不存在 `src/view/`（单数）。全局仅此一处写错。

**修复**：改为 `component: () => import('@/views/login/index.vue')`。

**验证**：`npm run build` 通过，产物中出现 `login-*.js` 分块。

**注意**：`src/router/index.js` 已被用户重构过，现在导出 `constantRoutes` + `asyncRoutes`（带 `meta.roles` 做权限），
并有 `/404` → `@/views/error/404.vue`（该文件确实存在）。目录约定仍是 `src/views/<模块>/index.vue`。

## 修复「全部页面白屏，加载不出来」（4 处拼写/误引入 bug）

项目已被用户重构为**动态路由 + 权限守卫**架构：
`main.js` → `import './router/permission'`（注册 beforeEach）→ `@/stores/permission`（`generateRoutes` 动态 addRoute）。
构建全部通过，但**运行时**报错导致白屏（构建期不会发现未定义标识符，这是关键排查点）。

1. **`src/stores/permission.js` 第 5 行：`definestore` → `defineStore`（大小写错）** ← **本次白屏的根因**
   该模块被 main.js 启动时直接加载，一执行就抛 `ReferenceError`，整个应用根本没启动 → 连登录页都白屏。
2. **`src/router/permission.js` 第 33 行：`return ture` → `return true`**
   守卫里 `ture` 未定义 → 登录后（token+userInfo 都有时走到这行）抛错 → 导航中断白屏。
3. **`src/router/index.js` 第 15 行**：删掉误引入的
   `import component from 'element-plus/es/components/tree-select/src/tree-select-option.mjs'`
   （IDE 自动补全误插入的 element-plus 内部文件，完全没用到）。
4. **`src/directives/permission.js` 第 7 行**：`!roles.includes(roles)` → `!roles.includes(role)`
   （原写法恒为 true，会把所有带 v-permission 的元素都删掉）。

**流程确认（无需再改）**：登录页 `handleLogin` 只调 `userStore.login()` 后直接 push，
**不**提前 fetchUserInfo → 守卫的 `!userStore.userInfo` 分支才会执行 → 调 `generateRoutes` 加动态路由 →
`return { ...to, replace: true }` 重新导航 → 命中 /dashboard。若登录页提前 fetch，该分支会被跳过导致动态路由没加上、依旧白屏。
登录页也已补上 `catch(e)`（此前缺 catch 导致的 Uncaught (in promise) 已解决）。

**遗留小问题（未改）**：`resetRoutes()` 在 logout 时没被调用，切换角色登录会重复 addRoute。
